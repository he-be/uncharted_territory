# 要件定義書：2D宇宙サンドボックスゲーム（仮）

## 1. はじめに

本ドキュメントは、これまでの技術検証（戦闘ミニゲーム、LLM連携、AvatarSystem）を統合し、開発フェーズを「技術デモ」から「ゲームプロトタイプ」へと移行するための要件定義書である。
特に、AIパートナー「A.L.V.A.」との体験を核とした、シングルプレイヤーの2D宇宙サンドボックスゲームの構築を目指す。

## 2. 既存ドキュメントの批判的検討と方針転換

### 2.1 実況から「伴走者」へ (memo_0104 vs memo_0105_2)

- **memo_0104（旧方針）**: 弾幕STGやFPSのような「実況コメンタリー」を志向。
  - _課題_: ゲーム体験がアーケードライクになりすぎ、サンドボックスの没入感を損なう可能性がある。また、すべてをLLMに依存するとキャラクターの一貫性が保ちにくい。
- **memo_0105_2（新方針）**: 探索・交易・戦闘を共にする「頼れる相棒（バディ）」としてのA.L.V.A.。
  - _採用理由_: プレイヤーの孤独な宇宙の旅に文脈と物語を与える存在として、実況者よりも「当事者」であるAIの方が適している。
  - _改善点_: memo_0104の「戦況への即応性（ルールベース）」は維持しつつ、人格と文脈（記憶）を重視する。

### 2.2 UI/UXの統合 (memo_0105)

- Python製の外部UIプロジェクトではなく、TypeScript/HTMLベースの`AvatarSystem`を本プロジェクトにネイティブ統合する。
- 既に実装済みの`AvatarSystem.ts`を拡張し、ゲームループおよびイベントシステムと結合させる。

## 3. ゲームコンセプト：Scrapyard Frontier

**「孤独な宇宙、二人きりの旅路」**

人類拡散（The Scattering）から300年。中央政府なき辺境宇宙「スクラップヤード・フロンティア」を舞台に、プレイヤーは一隻の老朽化した輸送船を駆り、生存と富を求めて航海する。

- **ジャンル**: 2Dトップダウン・宇宙サンドボックスRPG (Mount & Blade meets Space Sim)
- **コア体験**:
  1.  **自由な探索**: 星系間移動（ゲート航行）、ステーションへの寄港、未知の宙域探索といった一般的な4Xゲーの体験。
  2.  **ドローン戦闘**: 人間が耐えられない高G機動をこなす無人機（ドローン）を母艦から展開して戦う。
  3.  **A.L.V.A.との対話**: 「大拡散」以前の旧世代AIである彼女と共に、失われた記憶と世界を巡る物語を紡ぐ。

### 3.1 世界観に基づくメカニクス

- **No Shields (シールドなし)**:
  - エネルギーシールド技術は存在しない。防御は「機動回避（Evasion）」と「ポイントディフェンス（PD）」による迎撃、そして最終的な「装甲（Armor）」に依存する。
  - 被弾は即座に修理費（デスペナルティ）に直結する緊張感を生む。
- **Drone Warfare (ドローン戦争)**:
  - 有人戦闘は非効率（G耐性、生命維持、放熱）。戦闘はキャリア（母艦）から射出されるドローン同士の消耗戦が基本。
  - 母艦が落ちれば終わり。プレイヤーは「指揮官」として振る舞う。
- **Gate Network**:
  - FTL（超光速航行）は存在せず、古代の遺物「トランジットゲート」のみが星系間を結ぶ。ゲートのない星系は孤立している。

## 4. カスタマージャーニー / ストーリーボード（タイムライン）

プレイヤーのゲーム開始から初期ループまでの体験を時系列で定義する。

### Phase 1: Awakening (開始 - 5分)

- **Timeline**: 00:00 - 00:05
- **Scene**: ブート画面 〜 ヴェルデ星系（Verde System / 初期星系）
- **Action**:
  - ゲーム起動。システムログと共にA.L.V.A.が起動する。「300年ぶりだな」といった起動音。
  - A.L.V.A.は自身のメモリ破損（記憶喪失）を告げる。プレイヤーもまた、漂流船で目覚めた名もなき船長だ。
  - 基本操作のチュートリアル（スラスター点火、セクターマップ操作）。
- **Experience**: 「何もない宇宙に放り出された不安」と「相棒がいる安心感」の対比。

### Phase 2: The First Port (5分 - 15分)

- **Timeline**: 00:05 - 00:15
- **Scene**: 宇宙航行 〜 ポルタ・リベラ（Porta Libera / フリーポート）
- **Action**:
  - 最寄りのステーション「ポルタ・リベラ」への移動。
  - 道中、HI（ヘリオス・インダストリー）の輸送船団とすれ違う。
  - ドッキング許可申請と着艦。「無法地帯だが、今はここしか寄港できない」とA.L.V.A.の警告。
  - マーケットで燃料と物資を確認。「クレジット(cr)」がないと何もできない現実（経済的プレッシャー）。
- **Experience**: 世界の広がりと社会構造（勢力、経済）への接触。

### Phase 3: First Contact (15分 - 25分)

- **Timeline**: 00:15 - 00:25
- **Scene**: ヴェルデ外縁部（海賊領域）
- **Action**:
  - 小銭稼ぎのために「海賊討伐」または「サルベージ」の依頼を受諾。
  - 敵対勢力「レッドマスク（海賊クラン）」のスカウト船と遭遇。
  - **戦闘開始**: ベイ開放、Tier1スカウトドローンを展開。
  - A.L.V.A.の戦術支援。「敵機スクラップ化。ブラックボックス回収可能」。
  - 辛勝。ドローンを数機失うが、敵の残骸（スクラップ）を回収。
- **Experience**: 戦闘の緊張感（ドローンは消耗品）と、戦利品を得る喜び。

### Phase 4: Reflection & Expansion (25分以降)

- **Timeline**: 00:25 - End of Day 1
- **Scene**: ステーション帰還 〜 ゲートへの眼差し
- **Action**:
  - 戦利品を売却し、失ったドローンの補充と修理を行う。残金を見てため息をつく。
  - A.L.V.A.が「隣のカルデラ星系なら、工業部品が高く売れるかも」と呟く。
  - 次の目的地（トランジットゲート）への航路を引く。
- **Experience**: 生存サイクル（Combat-Loot-Trade）の確立と、広大な世界への期待。

## 5. システム要件

### 5.1 Avatar System Integration

既存の`AvatarSystem`クラスを拡張・統合する。

- **Event Driven**: ゲーム内イベント（`EnemyDetected`, `DockingRequested`, `BattleStarted`）を購読し、対応するセリフをトリガーする。
- **Dialogue Manager**:
  - **Priority System**: 戦闘中の警告（高優先度）は雑談（低優先度）を割り込んで再生する。
  - **Context Awareness**: A.L.V.A.の「記憶の断片」システム。特定の場所や勢力に対するユニークな反応を実装。
  - **Constraints**: 1回の発話は短く（タイプライターUI）、皮肉屋で実用主義的な性格を反映する。

### 5.2 Game Loop & State Management

- **Scene Management**: Phaser等のシーン管理を利用し、`SpaceScene`（宇宙航行・戦闘）と`StationScene`（ステーションUI）をシームレスに切り替える。
- **Persistent Data**:
  - **Player**: 所持金(cr)、機体状態、A.L.V.A.親密度。
  - **Fleet**: ドローン構成（Tier, 種類, 数）。
  - **World**: 各星系の市場相場、勢力関係。

### 5.3 Economy & Assets

- **Economy**:
  - ドローンは「装備」ではなく「弾薬/消耗品」として扱う経済バランス。
  - 維持費、修理費、補充費が常にプレイヤーの財布を圧迫する。
- **Assets**:
  - **Visual**: `c_alva_idle.png`, `c_alva_talk.png`。
  - **UI**: レトロフューチャーなターミナル風デザイン（青/琥珀色ベース）。

## 6. 世界観設定（用語集）

### 地名・勢力

- **星系**: ヴェルデ（初期）、カルデラ（工業）、リモージュ（富裕）、サルガッソ（墓場）。
- **勢力**: ヘリオス・インダストリー（HI）、リモージュ評議会（LC）、フリーポート連盟（FPL）、レッドマスク（RM/海賊）。

### 技術・用語

- **トランジットゲート**: 古代の遺産。星系間移動の唯一の手段。
- **ラジエータ**: 宇宙船の急所。破壊されると廃熱で機能停止（バーンアウト）する。
- **ドローンTier**: T1（スカウト）〜T5（ヘビーアサルト）。T6（エース）は非売品。

## 7. 開発ベストプラクティス

1.  **Component-Based Architecture**: 機能（移動、戦闘、AI、UI）を疎結合なコンポーネントとして実装する。ECSパターンの適用。
2.  **Single Source of Truth**: ゲーム状態（State）を一元管理する。
3.  **Iterative Prototyping**: まずは「移動→戦闘→報酬」の最小ループ（Minimum Viable Loop）を完成させる。

## 8. 今後のロードマップ

1.  **Phase 1**: ゲームループ基盤の実装（シーン遷移、ステータス管理）。
2.  **Phase 2**: A.L.V.A.イベントシステムの統合（トリガーベースの発話）。
3.  **Phase 3**: 戦闘バランス調整とエコシステム（経済）の簡易実装。
