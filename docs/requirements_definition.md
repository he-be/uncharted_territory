# 要件定義書：2D宇宙サンドボックスゲーム（仮）

## 1. はじめに

本ドキュメントは、これまでの技術検証（戦闘ミニゲーム、LLM連携、AvatarSystem）を統合し、開発フェーズを「技術デモ」から「ゲームプロトタイプ」へと移行するための要件定義書である。
特に、AIパートナー「A.L.V.A.」との体験を核とした、シングルプレイヤーの2D宇宙サンドボックスゲームの構築を目指す。

## 2. 既存ドキュメントの批判的検討と方針転換

### 2.1 実況から「伴走者」へ (memo_0104 vs memo_0105_2)

- **memo_0104（旧方針）**: 弾幕STGやFPSのような「実況コメンタリー」を志向。
  - _課題_: ゲーム体験がアーケードライクになりすぎ、サンドボックスの没入感を損なう可能性がある。また、すべてをLLMに依存するとキャラクターの一貫性が保ちにくい。
- **memo_0105_2（新方針）**: 探索・交易・戦闘を共にする「頼れる相棒（バディ）」としてのA.L.V.A.。
  - _採用理由_: プレイヤーの孤独な宇宙の旅に文脈と物語を与える存在として、実況者よりも「当事者」であるAIの方が適している。
  - _改善点_: memo_0104の「戦況への即応性（ルールベース）」は維持しつつ、人格と文脈（記憶）を重視する。

### 2.2 UI/UXの統合 (memo_0105)

- Python製の外部UIプロジェクトではなく、TypeScript/HTMLベースの`AvatarSystem`を本プロジェクトにネイティブ統合する。
- 既に実装済みの`AvatarSystem.ts`を拡張し、ゲームループおよびイベントシステムと結合させる。

## 3. ゲームコンセプト

**「孤独な宇宙、二人きりの旅路」**

- **ジャンル**: 2Dトップダウン・宇宙サンドボックスRPG (Mount & Blade meets Space Sim)
- **コア体験**:
  1.  **自由な探索**: 星系間移動、ステーションへの寄港、未知の宙域探索といった一般的な4Xゲーの体験。
  2.  **ドローン戦闘**: 母艦から展開されるドローンの艦載機バトル。サルベージ（レベルアップ）や維持コストが他のゲーム体験と統合される。
  3.  **A.L.V.A.との対話**: あらゆる行動に反応し、共に物語を紡ぐAIパートナー。

---

## 4. カスタマージャーニー / ストーリーボード（タイムライン）

プレイヤーのゲーム開始から初期ループまでの体験を時系列で定義する。

### Phase 1: Awakening (開始 - 5分)

- **Timeline**: 00:00 - 00:05
- **Scene**: ブート画面 〜 初期星系（宇宙空間）
- **Action**:
  - ゲーム起動。システムログと共にA.L.V.A.が起動する。
  - 「記憶がない」という設定の共有。プレイヤーとAIは対等な「初心者」としてスタート。
  - 基本操作のチュートリアル（移動、セクターマップ操作）。
- **Experience**: 「何もない宇宙に放り出された不安」と「相棒がいる安心感」の対比。

### Phase 2: The First Port (5分 - 15分)

- **Timeline**: 00:05 - 00:15
- **Scene**: 宇宙航行 〜 ポルタ・ステーション（ドッキング）
- **Action**:
  - 最寄りのステーション「ポルタ」への移動。
  - 道中、平和的な船団とすれ違い、世界が生きていることを実感する。
  - ドッキング許可申請と着艦。
  - ステーション内UIへの遷移。
  - マーケット情報の確認（「稼ぐ」ための動機付け）。
  - バーでの情報収集と「危険な依頼」の提示（リスクとリターンの学習）。
- **Experience**: 世界の広がりと社会構造（勢力、経済）への接触。

### Phase 3: First Contact (15分 - 25分)

- **Timeline**: 00:15 - 00:25
- **Scene**: 初期星系外縁部（戦闘宙域）
- **Action**:
  - 「海賊討伐」の依頼を受諾し、危険地帯へ。
  - 敵スカウト船団との遭遇。
  - **戦闘開始**: ドローン展開、指示出し。
  - A.L.V.A.による戦術支援（「敵ドローン展開」「回避しろ！」など）。
  - 辛勝と戦利品回収。
- **Experience**: 戦闘の緊張感と、共に死線を潜り抜けた連帯感。

### Phase 4: Reflection & Expansion (25分以降)

- **Timeline**: 00:25 - End of Day 1
- **Scene**: ポルタ・ステーション（帰還）
- **Action**:
  - 報酬受け取りと補給。
  - 新しい装備（Tier2ドローン）への投資計画。
  - 「明日はどこへ行こうか」という未来への展望。
- **Experience**: 成長の実感と、無限の自由への期待。

## 5. システム要件

### 5.1 Avatar System Integration

既存の`AvatarSystem`クラスを拡張・統合する。

- **Event Driven**: ゲーム内イベント（`EnemyDetected`, `DockingRequested`, `BattleStarted`）を購読し、対応するセリフをトリガーする。
- **Dialogue Manager**:
  - **Priority System**: 戦闘中の警告（高優先度）は雑談（低優先度）を割り込んで再生する。
  - **Cooldown**: 同じセリフの連呼を防ぐ。
  - **LLM Integration (Optional)**: 余裕があれば、定型文ではなくLLMによる動的生成を組み込むが、まずは高品質な定型文リスト（memo_0105_2参照）の実装を優先する。

### 5.2 Game Loop & State Management

- **Scene Management**: Phaser等のシーン管理を利用し、`SpaceScene`（宇宙航行・戦闘）と`StationScene`（ステーションUI）をシームレスに切り替える。
- **Persistent Data**: 所持金、燃料、ドローン構成、A.L.V.A.の好感度/記憶フラグを保持するSave System。

### 5.3 Assets

- **Visual**: `c_alva_idle.png`, `c_alva_talk.png` (表情差分)。
- **Audio**: タイプライターSE、環境音（宇宙船ノイズ、ステーション喧騒）。BGMは後で音声ファイルを追加予定。

## 6. 開発ベストプラクティス

開発においては以下の原則を遵守する。

1.  **Component-Based Architecture**:
    - 機能（移動、戦闘、AI、UI）を疎結合なコンポーネントとして実装する。ECS（Entity Component System）パターンの適用を継続・推奨する。
2.  **Single Source of Truth**:
    - ゲーム状態（State）は一箇所で管理し、UIやレンダラーはその状態を反映（React）する形式をとる。
3.  **Iterative Prototyping**:
    - まずは「移動→戦闘→報酬」の最小ループ（Minimum Viable Loop）を完成させる。装飾やサブクエストはその後に実装する。
4.  **Code Quality**:
    - TypeScriptの型安全性を最大限活用する。`any`型の使用は原則禁止。
    - ドキュメントコメント（JSDoc）を記述し、可読性を保つ。
