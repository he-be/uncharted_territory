新しいブランチを切って、戦闘のミニゲームについて、LLMによるセリフ生成とTTSの実験を続ける。
LLMはOpenrouterで使用し、APIキーは　.envファイルに記載がある。
LLMモデルは、一字一句間違えずに、　google/gemini-3-flash-preview　モデルを使わなければならない。決して他のモデルや、バージョンを使ってはならない。
TTSはあとで実装するので、今は何も設計しないように。

画面構成

以下の調査メモは弾幕シューティングの情報など関係ない内容があるし、LLMを使っているのに、L4Dなどの時代の静的な物量戦法から脱していないので、完全に採用せず、批判的に検討し、良いものだけ参考にすれば良い。決して全部採用しないように。またALVAはクール系の女性キャラとする。


# A.L.V.A. AIコンパニオン実況設計書：ドローン戦闘コメンタリーシステム

プレイヤーの行動と戦況に自動反応するAIコンパニオン「A.L.V.A.」の設計において、**ゲーム実況パターン、AIコンパニオンシステム、シナリオライティング手法**を統合した包括的なフレームワークを提示する。本設計は音声入力やダイアログ選択を使用せず、純粋にアクション・状況ベースの反応のみで構成される。

---

## 実況コメンタリーの核心パターン

ゲーム実況者とAIコンパニオンシステムの分析から、効果的なコメンタリーには**3つの層**が存在することが判明した。第一に「状況報告」として何が起きているかを伝える層、第二に「感情反応」としてその出来事への反応を示す層、第三に「戦術助言」として次の行動を示唆する層である。

Valveの『Left 4 Dead』では**1万行以上**のコンテキスト依存ダイアログを実装し、世界状態をフラットなkey-valueペアとして管理する「ファジーパターンマッチング」システムを採用している。このシステムでは「health=30」「enemies_nearby=5」のような事実群に対してルールをマッチングし、**最も具体的なルールが優先**される仕組みだ。Haloシリーズも同様に、初代で5,000、Halo 3では**35,000以上**のダイアログスニペットを実装している。

日本の実況プレイ文化では、**相槌文化**に基づく頻繁なリアクションが特徴的である。「やった！」「まじか！」「やばい！」といった短い感嘆詞を多用し、感情の振れ幅が大きい。西洋の実況者が30秒以上の沈黙を避けるのに対し、日本の実況者はより細かい間隔で反応を挟む傾向がある。

---

## STG/弾幕ゲーム特有のコメンタリー語彙

シューティングゲームコミュニティでは独自の専門用語体系が発達している。東方Projectを中心とした弾幕STGでは、**達成度を示す略語**が確立されており、「1CC」（ノーコンティニュークリア）、「NM」（ノーミス）、「NB」（ノーボム）、そして最高難度の「LNN」（Lunatic No Miss No Bomb）まで段階的に存在する。

Cave社のシューター（怒首領蜂、ケツイ、虫姫さま等）では、「GPS」（Get Point System：チェイン稼ぎ）、「撃ち返し弾」（敵破壊時の報復弾）、「弾消し」（ボム等による弾幕消去）といった**スコアアタック特有の用語**が使用される。「死ぬがよい」という怒首領蜂の象徴的フレーズは、ボス戦の緊張感を表現する際に引用される。

特に重要なのは「**抱え落ち**」（ボムを残して死ぬこと）への反応である。STGコミュニティではこれを最も悔しい死に方とみなし、「抱え落ちした...」「ボム撃って！」といった反応が頻出する。逆に「喰らいボム」（被弾直後のボム発動による死亡回避）の成功は高く評価され、「喰らいボム成功！」と称賛される。

## ダイアログシステム技術設計

### Valveルールベースシステムの適用

Left 4 Dの「ファジーパターンマッチング」を参考に、A.L.V.A.用のダイアログシステムを設計する。世界状態を**フラットなファクト群**として管理し、各ルールに対してマッチングを行う。

**ファクト定義例：**
```
player_health: 0-100
player_shield: 0-100
kill_streak: 0-N
death_streak: 0-N
enemies_nearby: 0-N
boss_active: boolean
battle_duration: seconds
ammo_percent: 0-100
momentum: -100 to +100
```

**ルール構造：**
```
Rule {
  criteria: [
    "player_health < 30",
    "kill_streak == 0",
    "death_streak >= 2"
  ],
  response_pool: ["厳しいな...", "立て直そう", "諦めるな"],
  priority: 高,
  cooldown: 15秒,
  play_count_limit: 3
}
```

### 優先度システム

| 優先度レベル | トリガータイプ | 例 |
|------------|--------------|-----|
| **最高** | 緊急警告 | 瀕死、ボス出現、包囲 |
| **高** | 状況変化 | シールド破壊、モメンタム転換 |
| **中** | 戦術情報 | 敵増援、リソース警告 |
| **低** | 褒め・励まし | キル称賛、回避称賛 |
| **最低** | アイドル | 長時間無音時の埋め |

### 反復回避メカニズム

1. **バリエーションプール**: 各トリガーに5-10種類のセリフを用意
2. **クールダウン**: 同一カテゴリのセリフは最低10秒間隔
3. **再生回数追跡**: 同一セリフは1戦闘中3回まで
4. **ランダム重み付け**: 直近使用セリフの選択確率を下げる
5. **コンテキスト排他**: 戦闘中は探索セリフを抑制

## 実装推奨アーキテクチャ

### トリガー評価フロー

```
[ゲームイベント発生]
        ↓
[ファクト更新] → player_health=45, kill_streak=3, etc.
        ↓
[ルールマッチング] → 条件を満たすルールを全て取得
        ↓
[優先度ソート] → 最も具体的（条件数多）なルールを選択
        ↓
[クールダウンチェック] → 最近発話したカテゴリを除外
        ↓
[バリエーション選択] → 未使用 or 使用回数少のセリフを優先
        ↓
[TTS発話] → 80文字以内のセリフを再生
```

### タイミング制御パラメータ

| パラメータ | 推奨値 | 説明 |
|-----------|-------|------|
| **最小発話間隔** | 3秒 | どんな状況でもこれより短い間隔で発話しない |
| **カテゴリクールダウン** | 10-15秒 | 同一カテゴリ（例：キル称賛）の再発話間隔 |
| **緊急割り込み許可** | 1秒 | 優先度「最高」のみ即座に割り込み可能 |
| **沈黙最大時間** | 30秒 | これを超えたらアイドルセリフを発動 |
| **戦闘後クールダウン** | 5秒 | 戦闘終了後、次の発話まで待機 |

### TTS最適化指針

1. **句読点の統一**: 「、」は0.3秒、「。」は0.5秒の間を作る
2. **感嘆符の制御**: 「！」は音声の強調度を上げるトリガー
3. **省略記号**: 「...」は0.7秒の間と音量低下
4. **文字数厳守**: 80文字超えは自動的に却下
5. **プリレンダリング**: 頻出セリフは事前生成してキャッシュ

## 結論と設計指針

本設計書は、プレイヤー音声入力なしで機能するAIコンパニオンA.L.V.A.の実況システムを提示した。**Valveのルールベースシステム**、**日本の実況文化**、**STGコミュニティの語彙**を統合することで、ドローン戦闘に特化した自然なコメンタリーが実現できる。

最重要の設計原則は**「沈黙の価値を知る」**ことである。Left 4 Deadでは1万行以上のダイアログがありながら、AI Directorは「リラックスフェーズ」を意図的に設けている。A.L.V.A.も全ての瞬間にコメントする必要はなく、**決定的瞬間の反応**と**適切な沈黙**のバランスが没入感を生む。

80文字制約は創造的制約として機能する。日本語の実況文化が示すように、「やった！」「まじか！」「やばい！」のような短い感嘆詞でも十分に感情は伝わる。簡潔さは弱点ではなく、リアルタイム戦闘の緊張感を損なわない**強み**である。
